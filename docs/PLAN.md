# BetterShot — Architecture & Implementation Plan

Source of truth for *what*: [REQUIREMENTS.md](REQUIREMENTS.md). This doc covers *how* and *in what order*.

## 1. Stack decisions

| Concern | Choice | Why |
|---|---|---|
| Language / UI | Swift 6, AppKit shell + SwiftUI views | Menu-bar agent, floating panels and global hotkeys need AppKit; SwiftUI for editor toolbar, preferences, popups. |
| Min OS | macOS 14 | `SCScreenshotManager` (ScreenCaptureKit still capture); Vision OCR. |
| Build | Swift Package (no Xcode project) + `scripts/bundle.sh` producing `BetterShot.app` | No generated project files, diff-friendly, `swift test` works in CI. |
| Capture | ScreenCaptureKit | Apple's supported path; window shadow, multi-display, recording. |
| OCR | Vision `VNRecognizeTextRequest` behind an `OCRProvider` protocol | English only at launch; languages are a parameter so packs can be added later. |
| Hotkeys | Small Carbon `RegisterEventHotKey` wrapper | No Accessibility prompt needed (req. §4.3). |
| Recording / GIF | AVFoundation (MP4) + ImageIO (GIF) | Native, no ffmpeg. |
| Persistence | `UserDefaults` (settings), Application Support (last-closed capture) | No database needed. |
| Tests | Swift Testing | Ships with the toolchain. |

No third-party dependencies at launch.

## 2. Module layout

Dependencies point strictly downward: `BetterShot` → `Services` / `Annotations` → `Core`.

```
Sources/
├── BetterShotCore/          Pure Swift. No AppKit, no I/O. Fully unit-testable.
│   ├── Capture/             CaptureMode, CaptureResult
│   ├── Settings/            AppSettings (Codable), FilenameTemplate, GIFExportSettings (+size estimate)
│   ├── Destinations/        UploadDestination protocol, ShareOutcome
│   └── OCR/                 OCRProvider protocol
├── BetterShotAnnotations/   Annotation document model + renderer (CoreGraphics). No UI.
│   ├── Model/               Annotation, AnnotationDocument
│   ├── History/             Undo/redo (value-type snapshots)
│   └── Render/              flatten(document) -> CGImage  (pixelate destructive here → req. §4.6)
├── BetterShotServices/      Side-effecting implementations of Core protocols.
│   ├── Capture/             ScreenCaptureKit capturer, scrolling stitcher
│   ├── Recording/           MP4 recorder, GIF encoder
│   ├── OCR/                 VisionOCRProvider
│   ├── Storage/             LocalStorage (last folder), RecentlyClosedStore (single slot)
│   └── Destinations/        GoogleDrive, OneDrive, ICloud, WhatsApp, Telegram
└── BetterShot/              App target (executable). AppKit/SwiftUI only.
    ├── App/                 @main, AppDelegate, dependency container
    ├── MenuBar/             NSStatusItem + menu (§3.1 items 1–17)
    ├── Capture/             CaptureCoordinator (permission → overlay → capture → hand-off), alerts, clipboard sink
    ├── Hotkeys/             Global shortcut registry + remapping
    ├── Overlay/             Crosshair/area/window selection windows
    ├── Preview/             Floating post-capture popup (§3.2)
    ├── Editor/              Editor window + toolbar (§3.3)
    ├── ResultBar/           "Drag me" bar + pinned image windows (§3.4)
    └── Preferences/         Settings window (§5)
Tests/                       One test target per library module.
docs/                        REQUIREMENTS, PLAN, reference screenshots.
scripts/                     bundle.sh (builds .app: Info.plist, LSUIElement, ad-hoc signing).
```

Folders appear as the phase that needs them lands — none are created empty.

### Key design points
- **One capture pipeline.** Every mode yields a `CaptureResult` (image or video URL). A single `CaptureCoordinator` runs *mode → capture → result → post-capture action* (popup / editor / auto-copy per Preferences). New modes plug in without touching UI.
- **Destinations are plugins.** `UploadDestination` (`id`, `displayName`, `share(_:) async throws -> ShareOutcome`). File hosts return a link; messaging targets hand off via clipboard/drag (no temp hosting, image-only — §4.9). Adding Dropbox/Slack/S3 = one new type + registration.
- **Annotations are data, not views.** Document is an immutable value; edits produce new values, so undo/redo is a snapshot stack and rendering is a pure function. Pixelate becomes destructive only at `flatten`, keeping editing non-destructive until Done.
- **Settings are one `Codable` struct** behind a small store, injected — no singletons beyond the app container.
- **Last closed capture only** — single-slot store, no history DB (§4.4).

## 3. Delivery phases (one or more commits per phase; tests first in Core/Annotations)

| # | Phase | Outcome |
|---|---|---|
| 0 | Scaffold | Repo, package, docs; `swift build` / `swift test` green. |
| 1 | Core models + settings | `AppSettings`, `FilenameTemplate`, `GIFExportSettings` (30 fps cap, presets, size estimate), tested. |
| 2 | Menu bar shell | Agent app (`LSUIElement`), status item, full §3.1 menu wired to a stub coordinator, `bundle.sh`. |
| 3 | Permission + fullscreen/area/window capture | ScreenCaptureKit, overlay, multi-display, Capture Previous Area. |
| 4 | Post-capture popup | Copy / Save (silent, last folder) / Pin / Cloud / auto-dismiss / click-to-edit. |
| 5 | Global hotkeys + Preferences | Remappable shortcuts; General, Shortcuts, Destinations tabs. |
| 6 | Annotation model + renderer | All tools as data, undo/redo, flatten, privacy test (pixelate irreversible). |
| 7 | Editor UI | Toolbar per reference, crop, merge tool, Save as…, Done. |
| 8 | Pin + result bar | Always-on-top pinned windows, "Drag me" bar, share sheet. |
| 9 | OCR (Capture Text) | Vision provider, English, text to clipboard. |
| 10 | Self-timer, Hide Desktop Icons, Open…, Restore Recently Closed | Small menu features. |
| 11 | Recording | MP4 default, PNG frame, GIF auto/manual with live size estimate. |
| 12 | Scrolling capture | Vertical + horizontal stitching. |
| 13 | Destinations | iCloud, Google Drive, OneDrive (OAuth), WhatsApp/Telegram handoff + web fallback. |
| 14 | Polish | Light/dark, VoiceOver labels, tooltips, <200 ms check, update check. |

**Status:** phases 0–14 done (all planned phases). Phase 14 is the polish pass. An audit found every icon-only control already has both a tooltip and a VoiceOver label (editor toolbar, popup, result bar, pins, recording HUD and card, shortcut recorder), and every floating surface (popup, bar, HUDs, toast, countdown) sits on system materials with white hairlines, so it follows light and dark; only the capture overlay is deliberately dark in both. New: **Check for Updates…** (the menu item was a stub) asks a GitHub-style "latest release" JSON feed, compares versions numerically (`1.10 > 1.9`; drafts, prereleases, non-https pages ignored) and offers to open the release page; nothing is downloaded or installed. The feed URL comes from `BETTERSHOT_UPDATE_FEED_URL` or Info.plist `BetterShotUpdateFeedURL` (https only; `scripts/bundle.sh` writes it), and without one the item says updates aren't set up in this build. **Latency:** each capture logs "Capture to preview took N ms" (warning above the 200 ms budget) from the capture request to the preview hand-off, in subsystem `com.bettershot.app`, category `capture`: check it with `/usr/bin/log stream --predicate 'category == "capture"'`. Not verified: the <200 ms figure itself (it needs a real capture with Screen Recording permission on real hardware), VoiceOver by ear, and a live update check (no release feed exists yet). Phase 13 summary: Phase 13 adds the cloud destinations behind the cloud button, chosen in the new **Preferences → Destinations** tab (the default-target picker moved there from General). **Google Drive** and **OneDrive** link through the system browser with OAuth 2.0 + PKCE and a loopback redirect on 127.0.0.1; tokens live in the Keychain and are refreshed automatically (a revoked grant unlinks the account). Uploads go to Drive's root (per-file scope) or OneDrive's `BetterShot` folder, then an anyone-with-the-link share is created and the link copied; if the host refuses a public link the file's own URL is copied and the toast says only the owner can open it. **iCloud Drive** copies into `iCloud Drive/BetterShot` (no entitlement needed because the app isn't sandboxed); a share link can't be made that way, so it reports "Saved to iCloud Drive" (the system link API is tried and used only if it works). **WhatsApp / Telegram** put the image alone on the clipboard (no caption) and open the installed desktop app, or the web client if none is installed; nothing is uploaded by BetterShot. OAuth client IDs come from `BETTERSHOT_GOOGLE_CLIENT_ID` / `_SECRET` / `BETTERSHOT_ONEDRIVE_CLIENT_ID` (environment wins) or matching Info.plist keys that `scripts/bundle.sh` writes from them; without an ID the Link button is disabled with "Not set up in this build". A failed upload keeps the capture in Restore Recently Closed File. Pure OAuth/redirect/token/handoff logic is in Core; PKCE, loopback server, authorizer and uploaders are tested against a fake HTTP transport (including the full link flow over a real loopback socket). Not exercised against the real services: no client IDs were available, so live Google/Microsoft sign-in and uploads, the Keychain store, iCloud Drive syncing and the WhatsApp/Telegram app launch are unverified. Phase 12 summary: Phase 12 adds scrolling capture. **Scrolling Capture** (vertical) and **Scrolling Capture (Horizontal)** — a visible second menu item rather than a hidden ⌥-alternate — let you pick an area; BetterShot then scrolls the content under it with posted wheel events (needs the **Accessibility** permission, requested with an explanatory alert), captures each step once the scroll animation has settled, measures how far the content really moved, and stitches only the new strips into one long image, which goes to the normal preview popup. A small HUD (kept outside the selected area so it can't swallow the scroll events) shows the frame count with Stop. The loop stops at the end of the content, a safety limit (80 frames / 30,000 px), Stop, or when it can't keep track; if a step overshoots the overlap it scrolls back and halves the step; if the first step moves nothing it probes the opposite wheel direction once. The decision logic is a pure `ScrollCaptureEngine` over a `ScrollingSurface` protocol, and the alignment is `ScrollStitcher` (per-row/column hashes, tolerant of sticky headers, small animations and blank regions); both are unit-tested against fake pages (exact reconstruction, wrong step sizes, overshoot, inverted wheel, unscrollable and ever-changing content). Not exercised on a real screen: the Accessibility-gated wheel posting (this build's process wasn't trusted, so the scroll-direction convention is unverified — hence the probe), ScreenCaptureKit timing, and behaviour in real apps (sticky footers repeat; infinite-scroll pages stop at the limits). Phase 11 summary: Phase 11 adds screen recording. **Record Screen** (menu) picks an area or, with Return, the whole display, then records an H.264 MP4 with ScreenCaptureKit at 30 fps (BetterShot's own windows, including the HUD, are excluded); a floating HUD shows elapsed time with Pause/Resume and Stop; the same menu item becomes "Stop Recording". Pausing drops frames and closes the gap via a pause-aware clock stamped on the host timebase, so a static screen's pause is still removed. No length or size limit (disk only). When stopped, a result card offers **Save MP4** (the default, silent save to the remembered folder), **Export GIF…** and Copy; it stays until acted on and unsaved recordings are kept in Application Support for a week (also reachable via Open…). **GIF export** has Auto (source frame rate capped at 30, Medium/128 colours/dithering on/100%) and Manual (10/15/20/24/30 fps, Low/Medium/High = 64/128/256 colours, dithering, 100/75/50%) modes with a live size estimate; because ImageIO can't limit palettes or dither, frames are quantised (median cut, Floyd–Steinberg) first. The mode persists as the default and is also editable in Preferences. Quitting mid-recording asks first, then stops and saves. PNG output is the existing still-capture path. Tests cover the writer, the full MP4→GIF pipeline (frame count, scale, colour limit, delay, loop) and the pure maths; the ScreenCaptureKit recorder itself, the HUD interactions and a real long recording are not exercised headlessly. Phase 10 summary: Phase 10 adds the four small menu features. **Self-Timer:** pick what to capture first (All-In-One overlay), then a 3/5/10 s countdown (Preferences → Capture) shown as a click-to-cancel HUD that never appears in the shot, then the capture. **Hide Desktop Icons:** the menu toggle hides them (Finder `CreateDesktop` + Finder restart) and shows a checkmark; they come back after the next capture unless "Keep desktop icons hidden after capture" is on, and on quit unless kept hidden; no-ops don't restart Finder. **Open…:** an image file opens in the editor, scaled by its DPI metadata when present (macOS Retina screenshots are 144 DPI), otherwise by the display's scale. **Restore Recently Closed File:** a single slot (Application Support, survives relaunch) filled when a capture is discarded — popup timed out / Esc / click-away / replaced, editor closed without Done, pin closed, result bar dismissed; restoring brings it back as the preview popup and empties the slot; the item is disabled when empty. Its ⌘Z is a menu key equivalent only (not a global hotkey, which would hijack Undo everywhere). Live Finder toggling was deliberately not exercised in tests (fakes only). Recording files (for Open…) arrive with phase 11. Phase 9 summary: Phase 9 adds on-device OCR (Vision, accurate mode, English only; the language is a parameter so more packs are a configuration change). Capture Text selects an area like Capture Area, recognizes it and copies the text in reading order to the clipboard, with a brief toast ("Reading text…" → "Copied N characters" / "No text found") and no preview popup. The editor's text highlighter now snaps to the words under the drag — one even band per line, merged across the words covered — falling back to the plain rectangle when no text is found; the whole image is recognized once per base image (pre-warmed when the tool is selected) and one drag is one undo step. The snapping and text-assembly rules are pure and unit-tested; the Vision call is tested against rendered text. First-ever use on a Mac can take ~20 s while Vision prepares its model (the toast covers it); later runs are fast. Language choice is not in Preferences yet. Phase 8 summary: Phase 8 adds pinned images (always-on-top, non-activating windows: drag by the background, resize from the edges with the aspect ratio locked, hover close button, right-click Copy / Save / Open in Editor / Delete) and the floating result bar (pin toggle, "Drag me" handle that moves the bar, Share via the system share sheet, Copy, Cloud; it dims when idle, brightens on hover and goes away after 30 s untouched or via Esc / right-click Dismiss). The bar appears after the editor's Done and after pinning from the popup or via "Pin to the Screen…". Copy / Save / Upload now live in one `ResultActions` used by the popup, bar and pins. Interpretation note: the bar's pin button toggles a pinned-image window for the same picture; the "Drag me" handle repositions the bar (per §3.4) rather than dragging the file out to other apps — say if file drag-out is wanted instead. Not yet exercised interactively. Phase 7 summary: Phase 7 adds the editor: a window with the reference toolbar (Crop, Merge, the 12 tools, colour / weight / arrow-style, Save as…, Done), an AppKit canvas for drawing, selecting, moving, resizing, inline text and crop, whole-editor undo/redo, and Save as PNG/JPEG/PDF. The logic that decides behaviour (shape gestures, resize handles, viewport, crop and merge of the base image) is pure and unit-tested in `BetterShotAnnotations`; the canvas only forwards points. The editor opens from the popup thumbnail or automatically after capture (Preferences), and Done returns to the popup (the floating result bar arrives in phase 8). The canvas re-renders the whole image per frame, which is simple but may feel slow on very large captures; cache the flattened base if that shows up. The editor UI has not been exercised interactively in CI or by the author — see the checklist in the PR/hand-off notes. Phase 6 summary: Phase 6 adds `BetterShotAnnotations`: an immutable annotation document (rectangle, filled rectangle, ellipse, line, arrow, text, pixelate, step counter, marker, pen, text highlight), per-annotation undo/redo, move/resize/crop, per-tool remembered styles, and a CoreGraphics flattener. Pixelate is destructive only at flatten time and is covered by tests that fail if it stops destroying detail. The module has no dependencies (not even Core). Editor tools are not wired to a UI yet (phase 7); the text highlighter is a plain tint until phase 9 snaps it to OCR'd text. Phase 5 summary: Phase 5 adds persisted settings, system-wide remappable capture hotkeys (Carbon, no Accessibility prompt) and a Preferences window with General and Shortcuts tabs. A separate Destinations tab is deferred to phase 13, when accounts can actually be linked; the default storage target lives on the General tab until then. GIF export controls arrive with recording in phase 11. Phase 4 summary: After a capture the preview popup appears bottom-right with Copy, Save (silent, remembered folder, never overwrites) and Upload (follows the default storage target; only Local exists yet). Pin is disabled until phase 8 and clicking the thumbnail does nothing until the phase 7 editor. Settings use defaults until phase 5 persists them. Interactive behaviour (overlay drag, Space-to-move, arrow nudging, window hover, multi-display, popup placement/dismissal) is implemented but needs manual verification with Screen Recording permission granted.

## 4. Risks & open items
- **Screen-recording permission (TCC):** ad-hoc rebuilds can re-prompt; `bundle.sh` signs with a stable identity when available (§4.3).
- **Scrolling capture** must drive another app's scroll (Accessibility or synthesized events) — highest risk; spike early in phase 12.
- **WhatsApp/Telegram detection** via `NSWorkspace` bundle-ID lookup; web fallback = clipboard image + open web client.
- **OAuth** for Drive/OneDrive needs client IDs from the product owner; read from config, never hardcoded.
- **iCloud** needs an entitlement + provisioning that plain SwiftPM can't carry; revisit packaging (Xcode project or signed bundle) at phase 13.
- Reference screenshots show another product's branding ("CleanShot"). BetterShot must not copy its name, icons or assets. `docs/reference/unrelated-form-validation.png` is a form-error screenshot with no bearing on this app.
